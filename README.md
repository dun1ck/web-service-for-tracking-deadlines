# Веб-сервис для учёта заданий и дедлайнов учебной группы

Кроссплатформенное клиент-серверное веб-приложение для централизованного планирования, мониторинга и контроля сроков сдачи учебных заданий студенческой группы.

---

## 🎯 Назначение и цели проекта

Сервис решает проблему академических задолженностей и потери информации о сроках сдачи учебных работ за счёт создания единого цифрового пространства группы:
* **Единый каталог дисциплин и заданий** (лабораторные, практические, курсовые, расчетно-графические работы, ДЗ) с прикрепленными методическими материалами и критериями оценивания.
* **Иерархический контроль дедлайнов** с автоматическим расчетом оставшегося времени и визуализацией «горящих» сроков.
* **Исключение дублирующих вопросов** старосте о вариантах, сроках и формулировках задач.
* **Прозрачный двухэтапный трекинг выполнения**: студент отмечает факт отправки на проверку, а староста верифицирует статус «Зачтено» по официальным результатам преподавателя.
* **Сводная аналитика успеваемости** группы для старосты и куратора в реальном времени с экспортом отчетов.

---

## 👥 Ролевая модель и доступ (RBAC)

1. **Гость** — доступ только к странице авторизации и регистрации по приглашению.
2. **Студент**:
   - Самостоятельная регистрация по уникальному инвайт-коду группы;
   - Просмотр заданий, методичек, назначенного варианта и календаря сроков;
   - Ведение персонального трекера сдачи работ («Не начато» → «В процессе» → «Сдано на проверку»);
   - Установка персональных приватных заметок и напоминаний.
3. **Староста (Администратор группы)**:
   - Управление составом группы (подтверждение заявок по инвайт-кодам, распределение по подгруппам);
   - Ведение справочника дисциплин и преподавателей;
   - Публикация и оперативный перенос дедлайнов (общих, подгрупповых, персональных);
   - Автоматизированное и ручное распределение вариантов заданий;
   - Публикация объявлений старосты (сущность `Announcement`);
   - Верификация сдачи работ (перевод в «Зачтено / Выполнено» или «На доработке»);
   - Сводная матрица успеваемости и экспорт отчетов (PDF, Excel/CSV).
4. **Преподаватель / Куратор** *(задел архитектуры)* — прямой доступ к проверке работ и выставлению ведомостей.

## 🔑 Ключевая бизнес-логика системы

* **Правило приоритета дедлайнов**: 
  $$\text{Действующий дедлайн} = \text{Персональный} \succ \text{Подгруппы} \succ \text{Общий}$$
  Официальные сроки имеет право изменять исключительно староста. Изменение общего срока не перезаписывает персональные отсрочки без явного подтверждения старосты.
* **Распределение вариантов**:
  Варианты детерминированно привязываются к конкретному студенту по ID. При добавлении новых студентов, переводах между подгруппами или изменении задания распределение вариантов у остальных студентов не «съезжает».
* **Верификация успеваемости**:
  Аналитика академических задолженностей строится строго на подтвержденных старостой статусах («Зачтено»), что исключает недостоверность данных при самоотчете.
* **Календарь и формула пиковой нагрузки**:
  Календарный день $d$ помечается индикатором «День высокой нагрузки», если на него приходится $N(d) \ge 3$ незачтенных дедлайнов.
* **Политика безопасности файлов**:
  Поддержка безопасной загрузки материалов (PDF, DOCX, XLSX, архивы ZIP/RAR/7Z до 50 МБ). Архивы инспектируются без распаковки на диск с блокировкой исполняемых файлов (`.exe`, `.bat`, `.sh`, `.cmd`, `.ps1`), паролей и защитой от zip-бомб (лимит распакованного объема до 200 МБ, коэффициент сжатия $\le 100:1$).
* **Ступенчатая защита от брутфорса**:
  5 некорректных попыток ввода пароля подряд $\rightarrow$ обязательная CAPTCHA; 10 попыток $\rightarrow$ временная блокировка аккаунта на 15 минут.
* **Защита персональных данных**:
  Обработка данных (ФИО, email, успеваемость) строго регламентирована в соответствии с **Законом Республики Беларусь от 7 мая 2021 г. № 99-З «О защите персональных данных»**.

## 🏛 Архитектура и стек технологий

* **Архитектурный шаблон**: трехзвенная клиент-серверная архитектура (SPA-клиент + REST API + Реляционная СУБД).
* **Frontend**: React 18 + TypeScript / Vite (Single Page Application, адаптивная вёрстка, навигация в 2–3 клика).
* **Backend**: Python 3.11+ (FastAPI), SQLAlchemy 2.0 (ORM), Alembic, Pydantic v2, Python-Jose (JWT), Bcrypt.
* **База данных**: PostgreSQL 15+ (14 таблиц, 7 ENUM, транзакционная целостность ACID, аудит изменений).
* **Кэширование и защита**: Redis 7 (Rate Limiting, учет попыток входа, CAPTCHA, сессии).
* **Хранилище файлов**: S3-совместимое объектное хранилище (MinIO).
* **Инфраструктура**: Docker Compose, Nginx, GitHub Actions CI/CD.

### Производительность и эргономика:
* Время первичной загрузки страницы (LCP): $\le 2.0$ сек (Fast 4G / Broadband).
* Время отклика REST API (p95): $\le 200$ мс.
* Правило навигации: доступ к любой ключевой функции не более чем за 2–3 клика от Главного дашборда.

## 🚀 Быстрый запуск

### Вариант 1: Полный стек в Docker Compose

1. Скопируйте шаблон переменных окружения:
   ```bash
   cp .env.example .env
   ```
2. Запустите все сервисы:
   ```bash
   docker compose up --build -d
   ```
3. Доступные адреса после запуска:
   * **Frontend (React SPA)**: `http://localhost` (порт 80)
   * **Backend REST API & Swagger UI**: `http://localhost:8000/docs`
   * **ReDoc документация**: `http://localhost:8000/redoc`
   * **OpenAPI JSON-спецификация**: `http://localhost:8000/openapi.json`
   * **MinIO Console (S3-хранилище)**: `http://localhost:9001` (логин: `minioadmin`, пароль: `minioadmin_secret`)

---

### Вариант 2: Локальный запуск Backend для разработки

1. Перейдите в директорию `backend`:
   ```bash
   cd backend
   ```
2. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv .venv
   # Windows:
   .\.venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Запустите сервер разработки:
   ```bash
   uvicorn app.main:app --reload --port 8000
   ```
5. Откройте интерактивную документацию Swagger UI: **[http://localhost:8000/docs](http://localhost:8000/docs)**.
